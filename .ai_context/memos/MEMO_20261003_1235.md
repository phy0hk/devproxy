# Sprint Memo — Instance Restart Fix, Log Separation, daisyUI/Tailwind Dashboard

**Date:** 2026-10-03 12:35
**Scope:** Instance lifecycle reliability, per-instance log isolation, dashboard UI framework

## What Was Built / Changed

### 1. Instance restart after stop/exit (root cause fix)

- **Root cause:** `process.Manager.Start` derived the process context from the HTTP
  request context (`context.WithCancel(ctx)`). When the `/api/processes/{name}/start`
  handler returned, the request context was canceled and `exec.CommandContext`
  killed the process. Startup via `StartAll(context.Background())` was unaffected,
  which is why "initial start works but UI start/restart does not".
- **Fix:** `Start` now uses `context.WithCancel(context.Background())`; the manager
  owns cancellation through `Stop`/`StopAll`.
- `Restart` now handles both cases: stops a live instance first, or starts a fresh
  instance when the previous one already exited (previously returned
  "process is not running").
- `wait` and `stop` now check ownership (`m.running[name] == process`) before
  mutating shared state, so a late waiter from an old instance cannot delete or
  overwrite the status of a newer restarted instance.

### 2. Log separation in the dashboard

- The terminal no longer mixes proxy routing telemetry into per-instance consoles.
- Views: `stdout` / `stderr` (per selected instance only), `lifecycle`
  (process.started/stopping/exited/failed for that instance), and a global `proxy`
  tab for `proxy.request` / `proxy.error` routing logs.
- SSE consumer fixed: the server sends named events (`event: devproxy`), so the
  client must use `addEventListener("devproxy", ...)` — `onmessage` never fires.

### 3. Dashboard UI with daisyUI + Tailwind

- `index.html` now loads daisyUI 4.12.14 (full.min.css) and the Tailwind CDN
  script; `data-theme="dark"`. No build step (assets are Go-embedded).
- Layout: navbar with connection badge, stat figures (managed / live / SSE),
  instance cards with state badges + Start/Restart/Stop buttons, terminal panel
  with bordered tabs.
- `app.css` reduced to terminal-specific styles (font, colors per stream, scroll).
- Note: dashboard requires internet access for the two CDN assets.

## Technical Notes

- Event contract (unchanged): `process.output` carries `process`, `stream`
  (stdout|stderr), `message`; lifecycle events carry `type`
  (`process.started|stopping|exited|failed`), `exit_code`, `error`;
  `proxy.request` carries `method`, `path`, `upstream`, `status`, `duration_ms`.
- Client-side buffers are capped at 400 lines per category; there is no server-side
  log history endpoint yet (a reconnect loses pre-connection lines).
- `Stop` waits up to 5s for graceful exit, then kills.

- Add a server-side log history endpoint (e.g. `GET /api/processes/{name}/logs`)
  so reconnects restore recent lines.
- Add per-run instance IDs to events to label restart boundaries in the terminal.

- UI interaction behavior (tab switching, clear, error toasts) is not covered by
  automated tests; verify manually in a browser.
