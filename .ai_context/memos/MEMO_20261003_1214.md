# Sprint Memo — Process Lifecycle, Dashboard, and Log Separation

**Date:** 2026-10-03
**Scope:** Restart reliability, instance output isolation, and embedded dashboard

## Implemented

- Process commands now remain independent of the request context that started them.
- Restart works after natural exit as well as after an explicit stop.
- Waiters only clear the instance they own, preventing a late exit from removing a newer restarted process.
- Process stdout and stderr continue through typed `process.output` events with an explicit stream field; proxy routing telemetry remains a separate event/log concern.
- Replaced the embedded dashboard shell with a local-only, responsive control-room UI styled with daisyUI/Tailwind-like utility patterns. No CDN, package, or runtime dependency was added.
- Added regression coverage for restart after exit and restart after stop.
